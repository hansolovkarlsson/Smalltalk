# 2026-09-14

The day was about the records, not the interpreter. Nothing under `src/`
changed; the two commits are the ones that gave this repository the
document set the other projects under `~/Projects` share, and this file is
the first entry the set has produced.

The setup was run in ensure mode, which is the mode where the danger is
duplication rather than damage. The audit went through `git ls-files`
rather than `ls`, because on a case-insensitive filesystem a test for
`docs/ROADMAP.md` answers yes for a `docs/roadmap.md` too. It found one
record already present, `docs/ROADMAP.md`, and found it doing two jobs at
once: the six ✅ milestones, each with its commit hash and a "Try it"
transcript, are the completed half of the ledger, and the "Beyond the
original roadmap" section is the open half. The standard shape splits those
into `ROADMAP.md` and `COMPLETED.md`. The decision was not to split. The
milestone entries are dense with cross-references to commits and the
transcripts the tutorial and language reference lean on, and pulling them
into a second file is a restructure with a real cost and no reader asking
for it. The new records link to the roadmap as "one ledger, both halves",
and `CLAUDE.md` says the same so a later session does not read the absence
of `COMPLETED.md` as a gap.

Three roles were genuinely missing: postmortem, journal, changelog. Before
calling any of them missing, the opening notes of the roadmap, the language
reference, the tutorial and the README were read for a written refusal,
since a project that has decided against a changelog usually says so in the
document that would otherwise have been one. None was found, so all three
were created, each with its opening note and an honest empty state. The
postmortem's empty state is the one worth a sentence here: the repository
has three real lessons already (the `GC_KIND_OOP_ARRAY` use-after-free, the
`strchr` scan running past `'\0'` into a reused REPL buffer, the
`internIndex()` realloc read through a stale pointer), all written into
`CLAUDE.md`'s architecture notes beside the code they explain. They were not
copied into the postmortem. Moving them is a choice about where the lessons
live, and that choice was left on the table rather than made as a side
effect of seeding a file.

Two edits were already sitting uncommitted in the working tree when the day
started: `scratch/` added to `.gitignore` with the standard comment, and a
"Start here" section at the top of `CLAUDE.md` pointing at
`scratch/daily-standup.md`. They were the right edits and were left exactly
as found, then committed together with the new records.

One thing the audit turned up that the standard did not anticipate: `docs/`
here is also the GitHub Pages site. It holds `.nojekyll`, a hand-written
`index.html` and `tutorial.html`, and a stylesheet, with no generator behind
them. That is not the generated-docs trap (nothing will overwrite a markdown
file placed there), but Pages serves every file in the directory, so the
new records are reachable by URL the same way `ROADMAP.md` and `LANGUAGE.md`
already were. The precedent was already set by those two, so the records
went into `docs/` as the standard says; the exposure is noted rather than
acted on.

The one edit to existing prose was asked for and granted: the sentence in
`CLAUDE.md`'s Roadmap section that listed the documents under `docs/` named
only two of them, and the additions had made that list incomplete. It now
names the tutorial and the records too. The suite was run before the
writing and after it, 24 tests both times, and `make examples` exits 0.
